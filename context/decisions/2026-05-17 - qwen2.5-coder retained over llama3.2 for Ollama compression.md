# Decision: qwen2.5-coder retained over llama3.2:3b for Ollama compression step

## Context
`llama3.2:3b` was installed. Evaluated whether to replace `qwen2.5-coder` as the default Ollama model in the orchestrator's summarizer node.

## Options Considered
1. **qwen2.5-coder** — code/data specialized, reliable structured output, follows formatting instructions consistently
2. **llama3.2:3b** — general-purpose, lighter (less VRAM), faster, not code-specialized

## Decision
Keep **qwen2.5-coder**. The Ollama node's job is technical compression (OHLCV tables, source code chunks) — tasks where code specialization directly improves accuracy. A general model would produce noisier summaries, degrading the quality of Claude's downstream reasoning.

## Consequences
- Claude's input stays high-signal; cost savings from the compression step are preserved
- Higher VRAM usage than llama3.2:3b
- If a future task is conversational/general-purpose, llama3.2:3b is the right swap

## Revisit If
- Ollama node is repurposed for non-technical summarization tasks
- VRAM pressure makes qwen2.5-coder impractical to keep loaded
- `qwen2.5-coder:1.5b` is benchmarked and proves sufficient quality at lower cost
